# Home Bot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local Windows service that relays agent events to a Telegram chat and returns inline-button confirmations to the agent, with dry-run as the default and no secrets outside a local `.env`.

**Architecture:** One Python process with two threads: a loopback-only HTTP bridge (`POST /notify`, `POST /ask`, `GET /answers`, `GET /health`, `GET /status`) and a Telegram `getUpdates` poller. Shared state lives in atomic JSON/JSONL files under `state/`; a fake Telegram transport makes every test run without network.

**Tech Stack:** Python 3.13.17, standard library only (`http.server`, `urllib.request`, `unittest`, `threading`, `json`, `hmac`, `hashlib`, `secrets`, `signal`), Telegram Bot API over HTTPS.

**Spec:** `E:\Projects\HomeBot\docs\superpowers\specs\2026-11-24-home-bot-design.md`

## Global Constraints

- Python 3.13.17; **standard library only** — no pip installs, no third-party packages.
- New code lives in `E:\Projects\HomeBot`; git initialized there; commit after every working task.
- Secrets only in local `.env` (gitignored); `.env.example` has empty keys only. Never print, log or commit token, chat ID or `LOCAL_API_KEY`.
- Default `SEND_ENABLED=0`: no Telegram network calls at all, including `getUpdates`. Enable only on explicit user instruction.
- HTTP server binds `127.0.0.1` only; every local request needs `X-HomeBot-Key`; body limit 64 KiB; `Content-Type: application/json`.
- Comments in code — Russian. User-facing text — Russian.
- Test command for every task: `python -m unittest discover -s tests -v` from `E:\Projects\HomeBot`.

## Review Focus

1. **Токен и ключ в логах/URL.** Ожидаемо: в логах только имя метода, полный URL и значения секретов никогда не печатаются. Тест: `tests/test_telegram.py::test_logs_never_contain_token` в Task 2.
2. **TTL и позднее нажатие кнопки.** Ожидаемо: агент получает `__timeout__` и не висит; поздний callback не создаёт второй ответ. Тесты: `tests/test_service.py::test_expire_writes_timeout_answer`, `test_late_callback_is_rejected` в Task 3.
3. **Переиспользование `id` и старый callback.** Ожидаемо: старый токен кнопки не привязывается к новому запросу. Тест: `tests/test_service.py::test_old_callback_token_invalid_after_id_reuse` в Task 3.
4. **Перезапуск процесса.** Ожидаемо: `offset`, `pending`, `answers`, `seq` восстанавливаются, дублей нет. Тесты: `tests/test_store.py::test_state_survives_reload`, `test_offset_roundtrip` в Task 1.
5. **Ошибки Telegram, 429 и длинный текст.** Ожидаемо: ограниченный backoff по `retry_after`, обрезка до 4096 символов, падение не происходит. Тесты: `tests/test_telegram.py::test_truncate_text`, `test_retry_after_honored` в Task 2.

- [ ] **Step 3: Implement `homebot/service.py`**

In dry-run `notify` appends to dry outbox and returns `{"ok": True, "queued": 1, "delivered": False}`; `ask` stores pending, appends dry outbox and immediately writes `__undelivered__`. When enabled, `send_message` with keyboard, store `message_id`/`chat_id`. `expire_due` iterates active pendings past TTL, calls `edit_reply_markup` best-effort, then `store.mark_expired`. `handle_callback` validates token against active pending, dedups by `callback_query_id` in a local set, writes `Answer` with chosen option, calls `answer_callback_query` and removes keyboard. `handle_command` supports `/start`, `/help`, `/status`, `/ping` only. All state access under one `threading.RLock` shared with the bridge and poller via service methods.
